# План запуска агента WeArt Studio для Threads

Пошаговая инструкция: что подключить, в каком порядке и как проверить каждый шаг.
Короткая справка по проекту лежит в `README.md`, правила для Claude Code в `CLAUDE.md`.

---

## 0. Что уже есть и в каком состоянии

Проект загружен в репозиторий `weart1/agent-thredds`, ветка `claude/busy-bell-bsyexa`.

Что проверено:

| Проверка | Результат |
|---|---|
| `npm ci` (установка зависимостей) | ок, Node 22 |
| `npm run check` (синтаксис) | ок |
| `npm test` (12 тестов) | все проходят |
| `npm run dev:mock` (запуск без ключей) | агент нашёл 30 тестовых постов, оценил 8, создал 5 черновиков |

**Как он работает, в двух словах:**

```
каждые 3 часа (SEARCH_CRON)
  → берёт следующие 6 ключевых слов по кругу
  → ищет посты в Threads (официальный API, 1 запрос = 1 из 500 в неделю)
  → отсеивает: уже виденные, свои, старше 48 ч, авторов, которым уже отвечали
  → Claude Haiku ставит каждому посту оценку 0–10
  → посты с оценкой ≥ 7 (не больше 8 за прогон) → Claude Sonnet пишет ответ
  → ответ попадает в «Очередь» в админке
  → ВЫ нажимаете «Отправить» → ответ публикуется в Threads

каждые 15 минут (MENTIONS_CRON)
  → проверяет, кто упомянул ваш аккаунт → черновик ответа в очередь
```

Сам агент без вас ничего не публикует. Исключение — настройка «Автоответ на упоминания»,
по умолчанию она выключена.

## 1. Что нужно подключить (сводка)

| # | Что | Зачем | Где | Стоимость |
|---|---|---|---|---|
| 1 | **Node.js 20+** | на нём работает агент | nodejs.org (локально), NodeSource (на сервере) | бесплатно |
| 2 | **Ключ Claude API** | оценка постов и написание ответов | console.anthropic.com | оплата за токены, см. шаг 2 |
| 3 | **Аккаунт Threads** (публичный) | от его имени уходят ответы | приложение Threads | бесплатно |
| 4 | **Приложение Meta** с Threads API | доступ к поиску, упоминаниям и публикации | developers.facebook.com | бесплатно |
| 5 | **App Review в Meta** для `threads_keyword_search` | без него поиск видит только ваши посты | кабинет приложения Meta | бесплатно, занимает дни или недели |
| 6 | **VPS-сервер** | чтобы агент работал круглосуточно | Hetzner, DigitalOcean, Timeweb и т.п. | ~5 $/€ в месяц |
| 7 | **Домен / поддомен** | адрес админки, например `agent.weartstudio.io` | DNS-панель вашего домена | уже есть |
| 8 | **Caddy** | https для админки (сертификат сам) | ставится на сервер | бесплатно |
| 9 | **Резервные копии** `data/db.json` | вся история и настройки в одном файле | cron на сервере | бесплатно |
| 10 | **Веб-аналитика с UTM** | видеть, сколько людей пришло из Threads | ваша аналитика сайта (GA4, PostHog, Метрика) | уже есть |

Порядок важен: **App Review (п. 5) подавайте как можно раньше**, потому что это самая долгая часть.
Пока Meta проверяет, можно всё остальное настроить и обкатать на упоминаниях.

## 2. Шаг 1 — посмотреть админку без ключей (5 минут)

На своём компьютере:

```bash
git clone https://github.com/weart1/agent-thredds.git
cd agent-thredds
git checkout claude/busy-bell-bsyexa   # пока изменения не слиты в main
npm install
npm run dev:mock
```

Откройте http://localhost:3000, пароль `mock-password`.

Что попробовать:
1. Нажать «Найти посты сейчас», в «Что делает агент» появятся шаги поиска.
2. В «Очереди» открыть черновик, поправить текст, переключить ссылку, нажать «Отправить».
   В mock-режиме ничего никуда не уходит.
3. Посмотреть «Оценки постов»: видно, почему каждый пост прошёл или отсеялся.
4. В «Настройках» поменять ключевые слова и порог оценки.

Тестовые данные пишутся в `data/mock-db.json`. Можно спокойно удалить файл, начнётся с нуля.

## 3. Шаг 2 — ключ Claude API

1. Зайдите на **console.anthropic.com**, зарегистрируйтесь или войдите.
2. **Billing** → пополните баланс (для начала хватит небольшой суммы).
3. **Limits** → поставьте месячный лимит расходов. Это защита, если что-то пойдёт не так.
4. **API Keys** → *Create Key* → назовите `threads-agent` → скопируйте ключ (`sk-ant-...`).
   Ключ показывается один раз.

Какие модели используются (меняются в `.env`):
- `FILTER_MODEL=claude-haiku-4-5-20251001` — дешёвая и быстрая, оценивает посты пачками по 20.
- `DRAFT_MODEL=claude-sonnet-5-5` — пишет ответы, только для лучших постов.

**Сколько это стоит.** Примерный объём при настройках по умолчанию: 8 прогонов в сутки,
до 8 черновиков за прогон. Это до ~64 коротких ответов Sonnet и несколько вызовов Haiku в сутки,
каждый по 1–2 тыс. токенов. Получается немного, но точную цену смотрите на странице
Pricing в консоли и в разделе **Usage** после первых дней работы.

## 4. Шаг 3 — аккаунт Threads и приложение Meta

### 4.1. Аккаунт Threads

- Аккаунт должен быть **публичным**.
- Лучше брать живой аккаунт бренда с аватаркой, описанием, ссылкой на weartstudio.io
  и хотя бы 5–10 своими постами. Пустой аккаунт, который только отвечает чужим,
  быстрее всего попадает под ограничения.
- Включите двухфакторную аутентификацию.

### 4.2. Аккаунт разработчика Meta

1. Откройте **developers.facebook.com** и войдите тем Facebook/Instagram-аккаунтом,
   к которому привязан (или будет привязан) Threads.
2. Если просит, пройдите регистрацию разработчика (подтверждение телефона).

### 4.3. Создание приложения

Названия пунктов в кабинете Meta иногда меняются, логика такая:

1. **My Apps → Create App**.
2. Сценарий (use case): **Access the Threads API**.
3. Название: например `WeArt Studio Agent`, контактный email.
4. Если спрашивают про бизнес-портфолио (Business Portfolio), привяжите компанию.
   Для App Review может понадобиться **верификация бизнеса**, лучше сделать заранее.

### 4.4. Разрешения (permissions)

В разделе use case → **Permissions** включите:

| Разрешение | Для чего |
|---|---|
| `threads_basic` | базовый доступ, имя аккаунта |
| `threads_content_publish` | публиковать ответы |
| `threads_manage_replies` | работать с ответами |
| `threads_keyword_search` | **поиск постов по ключевым словам** (нужен App Review) |
| `threads_manage_mentions` | читать упоминания вашего аккаунта |

### 4.5. Тестировщик

1. **App Roles → Roles → Add People → Threads Tester** → введите ваш Threads-юзернейм.
2. В приложении Threads: **Настройки → Аккаунт → Разрешения веб-сайтов → Приглашения** → примите.
   Без этого токен не выдаётся.

### 4.6. Ключи приложения

**App Settings → Basic** (для Threads часто отдельный блок *Threads App ID / Secret*):
- `THREADS_APP_ID`
- `THREADS_APP_SECRET`

Секрет никому не показывайте и не коммитьте в git.

### 4.7. Токен доступа

1. В кабинете use case → **Settings** / **User Token Generator** → *Generate Access Token*
   для вашего Threads-тестировщика. Такой токен живёт **1 час**.
2. Сразу обменяйте его на долгоживущий (60 дней):
   ```bash
   cp .env.example .env
   # впишите THREADS_APP_ID и THREADS_APP_SECRET в .env
   npm run token -- ВАШ_КОРОТКИЙ_ТОКЕН
   ```
3. Скрипт выведет длинный токен, вставьте его в `.env` как `THREADS_ACCESS_TOKEN`.

Дальше агент **сам продлевает** токен раз в неделю (ночное обслуживание в 04:00)
и хранит новый в `data/db.json`. Значение в `.env` нужно только при первом запуске.

> Нюанс: Meta разрешает продлевать токен не раньше чем через 24 часа после выдачи.
> При первом запуске в ленте может появиться ошибка «Не удалось продлить токен Threads».
> Это не страшно: токен рабочий, на следующую ночь продление пройдёт.

> Если агент простоял выключенным больше 60 дней, токен умрёт. Тогда повторите пункты 1–3
> и удалите из базы старый токен (или попросите Claude Code сделать это). Иначе агент возьмёт
> из `data/db.json` старый токен, а не новый из `.env`.

## 5. Шаг 4 — App Review для поиска (подать сразу)

Пока `threads_keyword_search` не одобрен, поиск возвращает в основном **ваши собственные посты**.
Тогда главная функция агента не работает. Упоминания и публикация работают и без одобрения.

Что обычно требует Meta (проверьте актуальный список в кабинете **App Review → Requests**):

1. **Privacy Policy URL**: страница политики конфиденциальности на weartstudio.io.
   В ней должно быть сказано, что вы обрабатываете публичные посты Threads для поиска обсуждений.
2. **Data deletion**: URL или инструкция, как пользователь может запросить удаление данных.
3. **Иконка приложения** 1024×1024 и категория.
4. **Описание использования для каждого разрешения.** Пример для `threads_keyword_search`:
   > Мы ищем публичные посты, где люди спрашивают совета по AI-инструментам для изображений,
   > видео и музыки. Найденные посты попадают во внутреннюю панель модерации. Сотрудник
   > вручную читает пост, при необходимости правит предложенный ответ и сам решает,
   > публиковать ли его. Автоматической массовой рассылки нет: не больше 20 ответов в сутки,
   > одному автору не чаще раза в 30 дней.
5. **Скринкаст** (видео 1–3 минуты): вход в админку → «Найти посты сейчас» → лента поиска →
   черновик в очереди → правка → «Отправить» → ответ появился в Threads.
   Записывать удобно, когда приложение ещё в режиме разработки и вы тестировщик.
6. После одобрения переключите приложение в режим **Live**.

Если отказали, прочитайте причину, поправьте описание и видео и подайте снова. Это обычная ситуация.

## 6. Шаг 5 — заполнить `.env`

```bash
cp .env.example .env   # если ещё не сделали
```

| Переменная | Что вписать |
|---|---|
| `PORT` | `3000` (оставить) |
| `ADMIN_PASSWORD` | длинный пароль, минимум 10 символов (лучше 20+) |
| `SESSION_SECRET` | результат `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `COOKIE_SECURE` | `false` локально, **`true` на сервере** с https |
| `THREADS_APP_ID` | из шага 4.6 |
| `THREADS_APP_SECRET` | из шага 4.6 |
| `THREADS_ACCESS_TOKEN` | долгоживущий токен из шага 4.7 |
| `ANTHROPIC_API_KEY` | ключ из шага 2 |
| `FILTER_MODEL`, `DRAFT_MODEL` | оставить по умолчанию |
| `SEARCH_CRON` | `0 */3 * * *` = каждые 3 часа (8 раз × 6 слов = 48 поисков в сутки, ~336 в неделю при лимите 450) |
| `MENTIONS_CRON` | `*/15 * * * *` = каждые 15 минут |

Если поставите поиск чаще, агент сам остановится при достижении недельного лимита (450 из 500).
Но тогда поиск будет простаивать до конца недели. Считайте: `прогонов в сутки × keywordsPerRun × 7 ≤ 450`.

## 7. Шаг 6 — первый боевой запуск локально

```bash
npm start
```

Откройте http://localhost:3000 и войдите с вашим паролем. В ленте «Что делает агент» должно быть:

- `Агент запущен, аккаунт @ваш_аккаунт` — Threads подключён.
- Если `Не удалось подключиться к Threads: ...` — проблема с токеном (см. «Если что-то не так»).

Дальше:
1. Нажмите **«Найти посты сейчас»**. До App Review, скорее всего, будет «Найдено 0» или только ваши посты.
2. Нажмите **«Проверить упоминания»**. Попросите кого-нибудь упомянуть ваш аккаунт в Threads
   и проверьте, что появился черновик.
3. **Отправьте один ответ вручную** и убедитесь, что он появился в Threads, а в «Отправленных» есть ссылка.

После проверки остановите агент (Ctrl+C) и переносите его на сервер.
Не запускайте агент одновременно локально и на сервере: у каждого своя база, и они ответят одним людям дважды.

## 8. Шаг 7 — сервер (VPS)

### 8.1. Купить сервер

- Hetzner (CX22), DigitalOcean (Basic 1 GB), Timeweb Cloud и т.п.: 1 vCPU, 1–2 GB RAM, Ubuntu 24.04.
- При создании добавьте свой SSH-ключ (`ssh-keygen -t ed25519`, публичная часть `~/.ssh/id_ed25519.pub`).

### 8.2. Базовая настройка

```bash
ssh root@IP_СЕРВЕРА

# Отдельный пользователь вместо root
adduser agent
usermod -aG sudo agent
rsync --archive --chown=agent:agent ~/.ssh /home/agent

# Файрвол: наружу открыты только SSH и https. Порт 3000 НЕ открываем.
ufw allow OpenSSH
ufw allow 80
ufw allow 443
ufw enable

# Обновления
apt update && apt upgrade -y
exit
```

Порт 3000 должен быть закрыт файрволом. Админка должна открываться только через Caddy (https).
Иначе пароль будет передаваться открытым текстом, и можно будет обойти блокировку подбора пароля.

### 8.3. Node.js 22 и pm2

```bash
ssh agent@IP_СЕРВЕРА
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
node -v          # v22.x
sudo npm install -g pm2
```

### 8.4. Код на сервере

**Вариант А (рекомендуется): через Claude Code командой `/deploy`.** Она проверяет тесты
и копирует код через rsync без `.env`, `data/` и `node_modules`. Перед этим создайте папку на сервере:
```bash
mkdir -p /home/agent/threads-agent
```
и заполните `CLAUDE.local.md` (см. раздел 11).

**Вариант Б: вручную через git.** Репозиторий приватный, поэтому нужен deploy key:
```bash
ssh-keygen -t ed25519 -f ~/.ssh/github_deploy -N ""
cat ~/.ssh/github_deploy.pub
# GitHub → weart1/agent-thredds → Settings → Deploy keys → Add (только чтение)
GIT_SSH_COMMAND="ssh -i ~/.ssh/github_deploy" git clone git@github.com:weart1/agent-thredds.git threads-agent
cd threads-agent && npm ci --omit=dev
```

### 8.5. `.env` на сервере

Секреты создаются на сервере вручную, в git их нет:
```bash
cd /home/agent/threads-agent
nano .env          # содержимое как локально, но COOKIE_SECURE=true
chmod 600 .env
```

### 8.6. Запуск через pm2

**Запускайте именно из папки проекта.** `.env` и `data/` ищутся относительно текущей папки.

```bash
cd /home/agent/threads-agent
pm2 start src/index.js --name threads-agent
pm2 save
pm2 startup        # выведет команду с sudo, скопируйте и выполните её
pm2 install pm2-logrotate   # чтобы логи не заняли весь диск
```

Полезные команды:
```bash
pm2 status
pm2 logs threads-agent --lines 50
pm2 restart threads-agent
```

### 8.7. Домен и https (Caddy)

1. В DNS вашего домена создайте запись **A**: `agent` → `IP_СЕРВЕРА`.
   Проверка: `ping agent.weartstudio.io` показывает IP сервера (иногда это занимает до часа).
2. Установите Caddy:
   ```bash
   sudo apt install -y caddy
   sudo nano /etc/caddy/Caddyfile
   ```
   Содержимое:
   ```
   agent.weartstudio.io {
       reverse_proxy localhost:3000
   }
   ```
3. `sudo systemctl reload caddy`. Caddy сам получит сертификат Let's Encrypt.
4. Проверьте: `curl -s https://agent.weartstudio.io/healthz` → `{"ok":true}`.
5. Откройте https://agent.weartstudio.io и войдите.

### 8.8. Резервные копии

Вся история, настройки и продлённый токен хранятся в `data/db.json`. Ежедневная копия:
```bash
mkdir -p /home/agent/backups
crontab -e
# добавить строку:
15 3 * * * cp /home/agent/threads-agent/data/db.json /home/agent/backups/db-$(date +\%F).json && find /home/agent/backups -name 'db-*.json' -mtime +30 -delete
```
Раз в неделю-две скачивайте копию к себе: `scp agent@IP:/home/agent/backups/db-ДАТА.json .`
Файл содержит токен Threads, храните его как пароль.

### 8.9. Мониторинг (по желанию)

Подключите бесплатный UptimeRobot или Better Stack на `https://agent.weartstudio.io/healthz`,
чтобы получать письмо, если агент упал.

## 9. Шаг 8 — первые недели работы

### Прогрев аккаунта

| Период | `maxRepliesPerDay` | Что делать |
|---|---|---|
| 1-я неделя | 5–10 | каждый ответ читать и править; публиковать и свои обычные посты |
| 2–3-я неделя | 10–15 | смотреть, на какие ответы реагируют |
| дальше | до 20 | не выше, если нет явной причины |

### Ежедневно (5–10 минут)

1. Открыть «Очередь», прочитать черновики: отправить, поправить или пропустить.
   **Пропуски и правки — сигнал агенту:** их анализирует `/agent-report`.
2. Пролистать «Что делает агент»: нет ли ошибок (красные строки).

### Раз в неделю

1. В Claude Code: `/agent-report` (или `/agent-report за 14 дней`).
   Он покажет, какие ключевые слова дают черновики, а какие только тратят лимит,
   и предложит готовый новый список.
2. Обновить ключевые слова в админке → «Настройки».
3. В веб-аналитике посмотреть трафик с `utm_source=threads&utm_medium=agent`:
   визиты, регистрации, оплаты.

### Ключевые слова

Сейчас их 18 (`keywords.json`), агент берёт по 6 за прогон по кругу.
Лучше всего работают формулировки, которыми люди **спрашивают**: «посоветуйте нейросеть»,
«какой сервис для видео», «what ai tool», «alternative to ...». Хуже работают названия моделей
(«nano banana», «seedance»): по ним много новостей и чужой рекламы.

### Чего не делать

- Не ставить `autoApproveMentions` в первый месяц.
- Не отвечать конкурентам и под их постами (фильтр это и так отсекает).
- Не поднимать лимиты резко: Threads ограничивает аккаунты за похожие повторяющиеся ответы.

## 10. Если что-то не так

| Симптом | Причина | Что делать |
|---|---|---|
| `Не задана переменная ... в .env` при старте | не заполнен `.env` | заполнить переменную, перезапустить |
| `ADMIN_PASSWORD должен быть не короче 10 символов` | короткий пароль | удлинить |
| `Не удалось подключиться к Threads: ... Invalid OAuth access token` | токен неверный или истёк | шаг 4.7 заново; если агент уже работал — удалить старый токен из базы |
| `Не удалось продлить токен Threads` в первый день | токену меньше 24 часов | ничего, на следующую ночь пройдёт |
| Поиск находит 0 постов или только ваши | нет App Review для `threads_keyword_search` | шаг 5 |
| `Недельный лимит поисковых запросов Meta исчерпан` | слишком частый `SEARCH_CRON` или много `keywordsPerRun` | уменьшить; лимит восстанавливается скользящим окном 7 дней |
| `Достигнут лимит N ответов за 24 часа` | сработал дневной лимит | подождать или поднять в настройках (осторожно) |
| Ошибки `Claude` / `401` / `credit balance` | ключ Anthropic или закончился баланс | проверить ключ и баланс в консоли |
| После входа сразу снова просит пароль на сервере | `COOKIE_SECURE=true`, а открыто по http | открывать по https |
| Сессии сбрасываются после каждого перезапуска | не задан `SESSION_SECRET` | задать в `.env` |
| `https://...` не открывается | DNS ещё не обновился или Caddy не запущен | `ping домен`, `sudo systemctl status caddy` |
| Агент не стартует после перезагрузки сервера | не выполнен `pm2 startup` | выполнить и `pm2 save` |

   - Папка на сервере: /home/agent/threads-agent

3. Готовые команды:
   - `/deploy` — тесты → показ изменений → копирование на сервер → перезапуск → проверка `/healthz`.

   а `npm start`, `ssh` и `rsync` выполняет только после вашего подтверждения.

- «добавь в админку фильтр по ключевому слову в оценках»
- «сделай, чтобы агент отвечал на комментарии под моими постами»
- «/agent-report за 14 дней»

## 12. Что можно улучшить в коде (бэклог)

По порядку пользы. Ничего из этого не нужно для запуска.

1. **Команда сброса токена.** Сейчас токен из `data/db.json` важнее `.env`. Если токен умер,
   новый из `.env` не подхватится, пока не удалить старый из базы. Нужна кнопка в админке
   или флаг: «использовать токен из .env».
2. **Первое продление токена.** Не пытаться продлевать токен в первые 24 часа после запуска,
   чтобы не было ложной ошибки в ленте.
3. **Предупреждение об истечении токена.** Показывать в шапке админки дату истечения и
   предупреждать за 7 дней, если продление не проходит.
4. **Ответы на комментарии под своими постами** (`threads_manage_replies` → чтение реплаев).
   Тёплая аудитория, ответы уместнее, чем в чужих ветках.
5. **Статистика эффективности.** Подтягивать лайки и ответы на наши реплаи
   (Threads Insights API, разрешение `threads_manage_insights`) и показывать, какие формулировки работают.
6. **Уведомления в Telegram**, когда в очереди появились черновики с оценкой 9–10.
   Их выгодно отправлять быстро, пока пост свежий.
7. **Разные UTM-метки на ключевое слово** (`utm_term=<keyword>`), чтобы в аналитике было видно,
   какие запросы приводят клиентов.
8. **Привязка сервера к localhost.** Слушать `127.0.0.1` вместо всех интерфейсов,
   чтобы порт 3000 был недоступен снаружи даже без файрвола.
9. **Хранилище.** JSON-файла хватает для одного агента. Если понадобится несколько аккаунтов
   или долгая история, стоит перейти на SQLite.
