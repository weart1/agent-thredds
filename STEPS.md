# Пошаговый план запуска: что делаете вы и что присылать мне

Короткий план по этапам. Подробности к каждому шагу есть в [PLAN.md](PLAN.md), номера разделов указаны в скобках.

Как пользоваться: проходите этапы по порядку. В конце каждого этапа блок **«📤 Скиньте мне»**.
Я проверю присланное и скажу, можно ли идти дальше, или исправлю код.

---

## ⛔ Никогда не присылайте мне

| Что | Где лежит |
|---|---|
| Ключ Runware | `RUNWARE_API_KEY` |
| Токен Threads (короткий и долгий) | `THREADS_ACCESS_TOKEN` |
| App Secret Meta | `THREADS_APP_SECRET` |
| Пароль админки и `SESSION_SECRET` | `.env` |
| Содержимое `.env` и `data/db.json` целиком | сервер |
| Приватные SSH-ключи, пароли от DigitalOcean, Vercel, Meta | — |

Если в выводе команды или на скриншоте виден ключ или токен, замажьте его или замените на `***`.
ID моделей, домены, IP сервера, логи агента и вывод `npm run report` присылать можно: секретов там нет.

## Этап 2. Runware (день 1, 15 минут)

**Вы:**
1. Зайдите на my.runware.ai, пополните баланс, создайте API-ключ (PLAN.md, раздел 3).
2. В каталоге runware.ai/models найдите две текстовые модели с поддержкой **tools / function calling**:
   - быструю и дешёвую, чтобы оценивать посты;
   - сильную, чтобы писать ответы (хорошо пишет по-русски).
3. Проверьте ключ и первую модель (вставьте свой ключ и ID модели):
   ```bash
   curl -s https://api.runware.ai/v1/chat/completions \
     -H "Authorization: Bearer ВАШ_КЛЮЧ" -H "Content-Type: application/json" \
     -d '{"model":"ID_МОДЕЛИ","messages":[{"role":"user","content":"Скажи привет"}],"max_tokens":50}'
   ```
   Повторите для второй модели.

**📤 Скиньте мне:**
- ID обеих моделей (например `anthropic:claude@sonnet-4.6`);
- ответ обеих команд `curl` (ключа в ответе нет, но проверьте сами).

**Я сделаю:** пропишу эти модели по умолчанию в коде и `.env.example` и проверю,
что формат ответа Runware совпадает с тем, что ждёт агент. Если не совпадает, поправлю код.

## Этап 3. Токен Threads и первый запуск на своём компьютере (день 1–2, 30 минут)

**Вы:**
1. На своём компьютере:
   ```bash
   git clone https://github.com/weart1/agent-thredds.git
   cd agent-thredds
   npm install
   cp .env.example .env
   ```
2. Впишите в `.env` `THREADS_APP_ID` и `THREADS_APP_SECRET`, сгенерируйте короткий токен в кабинете Meta
   и выполните `npm run token -- КОРОТКИЙ_ТОКЕН` (PLAN.md, 4.7). Долгий токен вставьте в `.env`.
3. Заполните остальное в `.env` (PLAN.md, раздел 6): пароль админки, `SESSION_SECRET`,
   `RUNWARE_API_KEY`, ID моделей. `ADMIN_ORIGIN` пока оставьте пустым.
4. Запустите `npm start`, откройте http://localhost:3000 и войдите.
5. Нажмите «Проверить упоминания». Попросите кого-нибудь упомянуть ваш аккаунт в Threads
   и отправьте **один** ответ вручную из админки.
6. Остановите агента (Ctrl+C). Не держите его включённым одновременно на компьютере и сервере.

**📤 Скиньте мне:**
- первые 20–30 строк, которые вывел `npm start` (секретов в них нет);
- скриншот админки после входа;
- ссылку на отправленный ответ в Threads (или текст ошибки, если не отправился);
- при ошибке на любом шаге — текст ошибки целиком.

**Я сделаю:** разберу ошибки, если они есть, и поправлю код.

## Этап 4. Сервер DigitalOcean (день 2, ~1 час)

**Вы:**
1. Подключитесь к droplet и выполните диагностику одной командой:
   ```bash
   lsb_release -ds; free -h | head -2; df -h / | tail -1; node -v 2>/dev/null; \
   which caddy nginx pm2 2>/dev/null; sudo ss -tlnp | grep -E ':80 |:443 |:3000 '; sudo ufw status
   ```

**📤 Скиньте мне (сначала это, до установки):**
- вывод этой команды;
- IP droplet (для DNS);
- работает ли на этом droplet что-то ещё (сайт, другие сервисы).

**Я скажу**, что именно ставить: Caddy или настройка в уже установленном nginx,
нужен ли файрвол, хватит ли памяти. И дам готовые команды под ваш сервер.

2. Дальше по моим командам (основа в PLAN.md, 8.2–8.6): Node 22, pm2, код, `.env` на сервере.
   **На сервере в `.env` обязательно** `COOKIE_SECURE=true` и
   `ADMIN_ORIGIN=https://agent.weartstudio.io`.
3. В DNS weartstudio.io добавьте запись **A** `api-agent` → IP droplet.
4. Настройте Caddy (или nginx) для `api-agent.weartstudio.io` (PLAN.md, 8.7).
5. Настройте бэкап базы (8.8) и включите Backups у droplet.

**📤 Скиньте мне (после установки):**
```bash
pm2 status
pm2 logs threads-agent --lines 30 --nostream
curl -s https://api-agent.weartstudio.io/healthz
```
- вывод этих трёх команд.

**Я проверю:** агент запущен, видит Threads и Runware, https работает.

**Чтобы я мог выкладывать обновления командой `/deploy`:** создайте у себя `CLAUDE.local.md`
(PLAN.md, раздел 11). `/deploy` запускается в Claude Code **на вашем компьютере**, где есть SSH-доступ
к серверу. Из облачной сессии я на сервер не захожу.

## Этап 5. Админка на Vercel (день 2, 20 минут)

**Вы:**
1. В Vercel импортируйте репозиторий `weart1/agent-thredds`, Framework Preset: **Other** (PLAN.md, 8б).
2. Добавьте переменную `API_URL` = `https://api-agent.weartstudio.io`.
3. Нажмите Deploy.
4. В Settings → Domains добавьте `agent.weartstudio.io` и создайте в DNS запись, которую покажет Vercel.
5. В Settings → Git укажите production-ветку `main`.
6. Откройте https://agent.weartstudio.io, войдите и нажмите «Проверить упоминания».

**📤 Скиньте мне:**
- скриншот админки на `agent.weartstudio.io` после входа;
- если сборка упала — лог сборки из Vercel (Deployments → нужный деплой → Building);
- если вход не проходит — скриншот вкладки **Console** в браузере (F12) и строку `ADMIN_ORIGIN`
  из `.env` сервера (это не секрет).

**Я сделаю:** разберу ошибки связки Vercel и сервера, если они будут.
